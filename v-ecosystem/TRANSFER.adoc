This document describes all V-lang work in the hyperpolymath estate that is
offered to the V community, following the ecosystem consolidation decision of
2026-04-10.

== Background

V-lang was seriously explored as the API transport layer of the hyperpolymath
ABI/FFI standard (Idris2 ABI → Zig FFI → V transport). Significant work was
produced: 107 connectors, 3 fully implemented protocol runtimes, 11 service
connectors, and a complete `v-ecosystem` monorepo directory within
`developer-ecosystem`. The decision to retire V from this estate was an
ecosystem-fit decision — too many parallel systems languages — not a
judgement on V as a language.

All work listed here is offered to the V community under
**PMPL-1.0-or-later**. PMPL-1.0-or-later is the primary stated licence;
until it achieves formal legal recognition, MPL-2.0 is the automatic
operative fallback — no separate request is needed. If an explicit
OSI-approved licence identifier is required for your package registry,
MPL-2.0 is available on request. The code is functional, documented, and
tested where noted.

== Fully Implemented Protocol Runtimes

These are the most complete and transferable pieces. Each is a standalone
GitHub repo with Idris2 ABI proofs, Zig FFI scaffold, and a working V-lang
transport layer.

=== v-grpc

*Repo:* https://github.com/hyperpolymath/v-grpc

gRPC-Web style JSON-over-HTTP server. Implements three RPC methods over
V's `net.http`: `Render`, `Context`, `Health` (dispatches to the Gnosis
CLI backend). Also includes `v-protoc` (`src/generator.v`) — a stub
generator that reads `.proto` files and emits V-lang service stubs.

ABI layer (`src/abi/`):

* Idris2 `Types.idr` — `Handle` with `So (ptr /= 0)`, `Result` with
  round-trip proofs, platform-aware `ptrSize`, `%default total`
* `Layout.idr` — memory layout verification
* `Foreign.idr` — `%foreign` C bindings for Zig FFI upgrade

Zig FFI scaffold (`ffi/zig/`) is present for the planned HTTP/2 +
Protobuf upgrade path — the Idris2 ABI layer is already wired for it.

*Status:* Transport complete and working. Zig FFI scaffold present but not
yet connected. Protobuf binary framing not yet implemented.

Already listed in https://github.com/vlang/awesome-v[awesome-v] under
*Networking*.

=== v-rest

*Repo:* https://github.com/hyperpolymath/v-rest

Conventional REST/JSON server for the same Gnosis backend. Four endpoints:
`POST /render`, `GET /context?scm=path`, `GET /health`, `GET /` (API
discovery). Notable detail: `/health` returns HTTP 200 (Gnosis reachable)
or HTTP 503 (Gnosis unavailable) — status-code semantics that load
balancers and container health checks can act on directly.

ABI layer (`src/abi/`) is identical in structure to v-grpc: same `Handle`
non-null proof, `Result` round-trips, `ptrSize` dependent on `Platform`,
`%default total`. Zig FFI scaffold (`ffi/zig/`) is present.

Main difference from v-grpc: conventional REST (GET/POST with query params
and `application/json`) rather than gRPC-Web path-based dispatch.

*Status:* Transport complete and working. Zig FFI scaffold present but not
yet connected.

Already listed in https://github.com/vlang/awesome-v[awesome-v] under
*Utilities*.

=== Service Connectors (11)

V-lang bridge stubs. Each follows the same RSR structure: a README,
source scaffold, and ABI/FFI directories. Each connector wraps a specific
service with a V-lang client interface.

**Note on service names:** These connectors were built against
hyperpolymath-internal services (BoJ, Hypatia, VeriSimDB, etc.). The
services themselves are not part of this donation. The connectors are
donated as working examples of V-lang client patterns against real API
surfaces — adapt the connection details for your own backend.

=== API Interface Scaffolds (95)

`v-api-interfaces/` contains 95 connector scaffolds covering the full
API protocol surface: WebSocket, JSON-RPC, MQTT, tRPC, SOAP, Cap'n Proto,
GraphQL, and 88 others. Each scaffold has:

* `README.adoc` — protocol description
* `TOPOLOGY.md` — architecture diagram
* `src/*.v` — V-lang stub (to be implemented)
* `ffi/zig/` — Zig FFI scaffold
* `.machine_readable/` — A2ML state files (structured metadata, self-describing)

These are clean starting points ready for V implementation.

Two additional entries landed in `v-api-interfaces/` as of 2026-04-17:

==== v-api-interfaces/v-proven

Thin V-lang FFI wrapper around `libproven`, a safe-operations library
covering overflow-checked arithmetic, XSS prevention, path traversal
protection, email/IP validation, and cryptographic token generation.

The V binding (`proven.v`, ~1 600 LOC) is a complete FFI shim; all logic
lives in Idris2 with Zig and Rust alternative bindings also available.

**Licence:** PMPL-1.0-or-later (MPL-2.0 legal fallback).

This file was previously part of the hyperpolymath `verification-ecosystem`
repo under `proven/bindings/v/`. It is being donated here because the V
binding is complete and useful, but the hyperpolymath estate is moving to
Zig/Rust for all FFI bindings. See `v-api-interfaces/v-proven/MIGRATION.adoc`
for the migration context.

==== v-api-interfaces/v-bebop

V-lang FFI bindings for the Bebop binary serialisation protocol, plus IIoT
client and server examples using V's standard `net` library.

Files:
* `bebop_bridge.v` — module binding the C ABI from `include/bebop_v_ffi.h`
* `iiot_client.v` — IIoT sensor data client
* `iiot_server.v` — IIoT sensor data server
* `v.mod` — V module manifest

**Licence:** AGPL-3.0-or-later (note: different from the rest of this bundle
which is PMPL-1.0-or-later). This code originated in the hyperpolymath
`bebop-ffi` project; the AGPL reflects the licensing of the Bebop wire-format
binding work done in that project.

This directory was previously `developer-ecosystem/bebop-v-ffi/v/`.

==== VeriSimDB API stubs (in v_api_interfaces/)

`v_api_interfaces/` (note: underscore variant; both directories are included
in this transfer) contains additional connectors including three VeriSimDB-
specific stubs:

* `verisimdb_graphql/` — GraphQL gateway for VeriSimDB hexad storage (port 9092)
* `verisimdb_grpc/` — gRPC interface to VeriSimDB
* `verisimdb_rest/` — REST interface to VeriSimDB

VeriSimDB is an internal hyperpolymath formal-verification database. These
stubs are donated as working examples of GraphQL/gRPC/REST gateway patterns
in V, even though VeriSimDB itself is not being donated. The stubs will
require adaptation to connect to a different backend.
