= rescript-tea
:toc: preamble
:icons: font
:source-highlighter: rouge

**The Elm Architecture for ReScript** -- a comprehensive, standalone implementation.

== Why This Exists

The original https://github.com/nickytonline/rescript-tea[rescript-tea@0.16.0] is unmaintained and depends on the legacy `bs-dependencies` system. Modern ReScript (v12+) uses `dependencies` in `rescript.json` and produces ES modules. This project is a ground-up reimplementation that:

* Works with ReScript 12+ and `@rescript/core`
* Uses ES module output (`esmodule` in `package-specs`)
* Provides keyed virtual DOM diffing for efficient list rendering
* Includes server-side rendering (SSR) for testing, snapshots, and static generation
* Ships with Elm-style JSON decoders (no Js.Json, no bs-json)
* Includes a time-travel debugger, HTTP module, and a test harness
* Has zero runtime dependencies beyond `@rescript/core`

== Installation

Add `rescript-tea` to your project. The source lives in `src/tea/` and compiles to `.res.js` files in-source.

[source,json]
----
// rescript.json
{
  "sources": [{"dir": "src/tea", "subdirs": true}],
  "package-specs": [{"module": "esmodule", "in-source": true}],
  "suffix": ".res.js",
  "dependencies": ["@rescript/core"]
}
----

[source,json]
----
// deno.json
{
  "tasks": {
    "res:build": "deno run -A npm:rescript build",
    "res:watch": "deno run -A npm:rescript build -w",
    "test": "deno test tests/"
  },
  "imports": {
    "rescript": "npm:rescript@^12.0.0",
    "@rescript/core": "npm:@rescript/core@^1.0.0"
  }
}
----

== Quick Start

[source,rescript]
----
// Counter.res — A minimal TEA counter application.

type model = int
type msg = Increment | Decrement

let init = () => (0, Tea_Cmd.none)

let update = (model, msg) => {
  switch msg {
  | Increment => (model + 1, Tea_Cmd.none)
  | Decrement => (model - 1, Tea_Cmd.none)
  }
}

let view = model =>
  Tea_Vdom.nodeA("div", [], [
    Tea_Vdom.nodeA("button", [Tea_Vdom.onClick(Decrement)], [Tea_Vdom.text("-")]),
    Tea_Vdom.nodeA("span", [], [Tea_Vdom.text(Int.toString(model))]),
    Tea_Vdom.nodeA("button", [Tea_Vdom.onClick(Increment)], [Tea_Vdom.text("+")]),
  ])

let app = Tea_App.standard(
  ~init,
  ~update,
  ~view,
  ~subscriptions=_ => Tea_Sub.none,
  "app",
)
----

== Module Reference

[cols="1,3"]
|===
|Module |Description

|`Tea`
|Re-exports and top-level convenience bindings.

|`Tea_App`
|Application bootstrap: `standard`, `beginner`, and `debug` program types. Mounts to a DOM node and runs the TEA event loop.

|`Tea_Vdom`
|Core virtual DOM types and constructors: `Text`, `Element`, `KeyedElement`, `Fragment`. Comprehensive attribute and event helpers (click, input, keyboard, pointer, drag, clipboard, ARIA). `map` and `mapAttr` for composing nested components.

|`Tea_Cmd`
|Side-effect commands: `none`, `msg`, `batch`, `call`, `map`, `execute`. Integrates async operations (Promises, timers) into the TEA cycle.

|`Tea_Sub`
|Subscriptions to external event sources: `none`, `registration`, `batch`, `map`, `getKeys`, `enable`. Used for timers, WebSockets, browser events.

|`Tea_Html`
|Convenience HTML element constructors built on `Tea_Vdom`. Provides `div`, `span`, `button`, `input`, `form`, `table`, etc.

|`Tea_Svg`
|SVG element and attribute constructors for inline SVG rendering.

|`Tea_Json`
|Elm-style JSON decoders: `string`, `int`, `float`, `bool`, `null`, `field`, `optionalField`, `at`, `array`, `index`, `dict`. Combinators: `map`, `map2`...`map5`, `andThen`, `oneOf`, `optional`, `nullable`, `succeed`, `fail`, `value`. Includes `decodeString`, `errorToString`, and `toHttpDecoder`.

|`Tea_Http`
|HTTP request module: `get`, `post`, `request`, `expectJson`, `expectString`. Integrates with `Tea_Json` decoders for type-safe API calls.

|`Tea_Ssr`
|Server-side rendering: `toString`, `toStringPretty`, `toDocument`. Renders virtual DOM to HTML strings without a browser DOM. Handles void elements, HTML escaping, boolean attributes, and style collection.

|`Tea_Render`
|Browser DOM renderer: patches the real DOM by diffing old and new virtual DOM trees. Handles keyed children with O(n) reordering.

|`Tea_Debug`
|Time-travel debugger: wraps any TEA application with a debug panel showing message history, model state, and the ability to replay/rewind.

|`Tea_Time`
|Time subscriptions: `every` (periodic timer), `delay` (one-shot). Produces messages at specified intervals.

|`Tea_Keyboard`
|Keyboard event subscriptions: `downs`, `ups`, `presses`. Captures key events globally.

|`Tea_Mouse`
|Mouse event subscriptions: `clicks`, `moves`, `downs`, `ups`. Captures mouse events globally.

|`Tea_Window`
|Window event subscriptions: `onResize`, `onScroll`. Captures browser window events.

|`Tea_Animationframe`
|Animation frame subscriptions for smooth 60fps updates. Produces messages on each `requestAnimationFrame` tick.

|`Tea_Test`
|Test harness for TEA applications: `simulate`, `send`, `sendAll`, `model`, `messageHistory`, `messageCount`, `assertModel`, `runScenario`, `viewSnapshot`. Test the model-update-view cycle without a DOM.
|===

== Feature Highlights

**Keyed Diffing**::
`Tea_Vdom.keyedA` enables O(n) list reordering. When items are added, removed, or reordered, the renderer moves DOM nodes instead of recreating them. Essential for performant lists.

**Server-Side Rendering**::
`Tea_Ssr.toString` and `Tea_Ssr.toStringPretty` render virtual DOM to HTML strings. Use for snapshot testing, static site generation, or server-rendered pages.

**Elm-Style JSON Decoders**::
`Tea_Json` provides composable, type-safe decoders that produce clear error messages with path context. No more `Js.Json.classify` chains.

**Time-Travel Debugger**::
`Tea_Debug` wraps any application with a debug panel showing the full message history and model state at each step. Replay and rewind to any point.

**Fragment Support**::
`Tea_Vdom.fragmentA` renders children without a wrapper `<div>`. Avoids unnecessary DOM nesting.

**Comprehensive Event System**::
Mouse, pointer, touch, keyboard, drag-and-drop, clipboard, animation, scroll, and form events with proper `preventDefault` and `stopPropagation` support.

**ARIA Accessibility**::
Built-in attribute helpers for `aria-label`, `aria-live`, `aria-expanded`, `role`, and many more ARIA attributes.

deno task res:watch
