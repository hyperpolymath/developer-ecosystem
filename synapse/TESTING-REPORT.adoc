== Unit Test Analysis

=== Parser Tests

The `rust_parser.zig` module contains the following test:

[source,zig]
----
test "parse simple struct" {
    const allocator = std.testing.allocator;
    const source =
        \\#[derive(Synapse)]
        \\pub struct Player {
        \\    pub name: String,
        \\    pub score: i32,
        \\}
    ;

    var structs = std.ArrayList(RustStruct).init(allocator);
    defer {
        for (structs.items) |*s| s.deinit();
        structs.deinit();
    }

    try parseRustStructs(source, &structs, allocator);

    try std.testing.expectEqual(@as(usize, 1), structs.items.len);
    try std.testing.expectEqualStrings("Player", structs.items[0].name);
}
----

=== Issues Identified

==== Issue 1: Missing SPDX Headers in Workflows

Most workflow files lack SPDX license headers. Only `mirror.yml` has the required header:

[source,yaml]
----
# SPDX-License-Identifier: PMPL-1.0-or-later
----

==== Issue 2: Unpinned GitHub Actions

The following workflows use version tags instead of SHA-pinned actions:

- `codeql.yml`: `actions/checkout@v6.0.1` (should be SHA-pinned)
- `quality.yml`: `trufflesecurity/trufflehog@main` (should be SHA-pinned)
- `quality.yml`: `editorconfig-checker/action-editorconfig-checker@main` (should be SHA-pinned)
- `guix-nix-policy.yml`: `actions/checkout@v6.0.1` (should be SHA-pinned)

==== Issue 3: Missing Workflow Permissions

The following workflows lack explicit `permissions: read-all`:

- `codeql.yml` (has job-level but not workflow-level)
- `quality.yml`
- `guix-nix-policy.yml`

== Known Limitations

As documented in CHANGELOG.md:

1. Generic type parameters not extracted (`Vec<String>` maps to `[Any]` not `[String]`)
2. No enum support
3. No nested struct support
4. Timestamp in generated header is static "TIMESTAMP" string
